# Portal JSON parser

Ported from `geant-config-generator/tests/geant4/fanoCavity/parser.py`, which
targeted the old `gts.BaseParser` queue API (`Test.parse(self, jobs)` over a
list of repeated-seed job dicts carrying a `ROVER` key). The CI in this
organization (`ci-workflows/validation/export.py`) instead loads
`validation/parser.py` as a standalone module and calls module-level
`metadata(commands)` / `parse(job)` once per macro — this parser was
rewritten for that API, the same pattern used by `TestDEDX2`, `CCCStest`,
`Attenuation-ilantest` and `LowEFrag` in this organization.

`(Dose/EnergyFluence)/Mass_energy_transfer = <ratio> +- <error>` is printed to
stdout by `Run.cc` at end-of-run; `parse()` reads it from the captured
`test_stdout.txt`, unchanged from the original parser's `extractObservable`.

## What changed structurally, and why

The original test sweeps `/process/eLoss/StepFunction %ROVER% 10 um` (the
dR/Range stepping-precision parameter, **not** a geometry ratio) over 14
values, with 100 repeated random seeds per value, submitted as one job group;
the old parser averaged the repeats and plotted the 14 `(ROVER, mean ratio)`
points as one chart.

The new per-macro pipeline has no job-group/repeat-seed concept: each macro
produces exactly one `test_stdout.txt`. So `parse()` here yields **one
single-point chart per macro** (`nPoints: 1`, no seed averaging) instead of
the original's 14-point averaged curve; the portal is expected to combine
records that share `testName`/`title`/`targetName`/`mctool.model` across the
separate `plots/*.json` files into the same displayed curve, the same way
`CCCStest`'s per-isotope records or `TestDEDX2`'s per-cut records already
rely on the pipeline treating each parser-yielded record as one series/point
rather than one file === one whole chart.

`config.json` lists 14 concrete macros, `standard_opt0_ROVER_<value>.mac`,
one per `ROVER` value in `geant-config-generator/tests/geant4/fanoCavity/params.conf`,
all for the `standard_opt0` physics list — generated by substituting
`template.conf`'s `%RANDOMSEED%`/`%PHYSLIST%`/`%ROVER%`/`%NEVENTS%`
placeholders (`params.conf`'s `100*` seed-repeat prefix was dropped: one run
per `ROVER` value, not 100). The other three reference physics lists in
`params.conf` (`standard_opt3`, `standard_opt4`, `standard_GS`) are not
included — generate their own 14-macro sets the same way if needed, by
substituting `%PHYSLIST%` with the other value.

Beam particle/energy (gamma, 1.25 MeV) are hardcoded in
`PrimaryGeneratorAction.cc`, not macro-configurable, so `metadata()` does not
read them from the macro — `parse()` fills them in as constants instead,
matching the original parser's unconditional `beamParticle=job["PARTICLE"]`
(which only ever held the literal `"gamma"` for this test).

`PRECISE`-decimal rounding from the original `extractObservable` is dropped;
`float()` is sufficient here since the CI's `validate_record` rejects
NaN/Infinity directly and the portal format stores IEEE floats regardless.
